# Agent Note: 账号设备与出站远程中转

Status: implemented

[English](2026-08-15-account-device-remote-relay.md) | 中文

## Problem

直接[局域网访问](2026-08-15-authenticated-lan-web-access.zh.md)无法让移动网络中的手机连接家庭路由器后的电脑，而把 Harness 监听器暴露到公网既要求端口映射，也会让具备命令执行能力的应用占用公共入站端口。远程使用需要账号所有权、按设备撤销和服务器中转，并且不能要求桌面端接收官网密码，也不能让中转服务器选择任意本地目标。

## Decision

**官网负责用户、设备与连接准入。** 独立部署的 Go、MySQL 与 Vue 3 服务提供注册、登录、用户中心、设备中心、浏览器设备批准、在线状态与一次性中转票据。该服务刻意位于本仓库之外，因为公网服务拥有独立的数据、密钥、部署、扩缩容与事故责任。桌面端只在 owner-only 的 `remote-access.json` 中保存带版本的官网 origin、明确启用状态和设备凭据；服务端只保存设备与会话 token 的 SHA-256 摘要。

**桌面授权使用系统浏览器，并在启动时提供账号引导。** 当安装实例没有持久化设备授权时，桌面端会在创建产品窗口前说明登录后可从手机或其他设备使用本机。用户可以开始浏览器授权，也可以跳过提示继续仅在本机使用；已授权的安装实例不会再次显示该提示。桌面端申请短期高熵设备码，打开官网同源批准页面，并轮询到已登录用户批准为止。设备 token 使用服务端密钥从设备码摘要派生，只返回一次，桌面端不需要收集账号凭据。授权与远程控制仍彼此独立：批准后远程控制保持关闭，必须在成功提示、应用菜单或仅桌面端显示的「通用设置」行中明确开启。未绑定账号的用户选择远程控制时会再次进入授权流程，成功前不能启动隧道。设置行调用与原生菜单相同的 Electron 弹窗，并且不出现在局域网页和官网远程页中。

**已启用设备建立一条经过认证的出站 WebSocket。** 主进程使用设备 token 连接官网，并在偏好保持开启时自动重连。公网中转只通过该连接复用有界 `/api` 请求与业务 WebSocket 流；中转端和桌面端都会拒绝非 API 隧道目标。每个请求目标都相对于已就绪 Harness 回环 origin 解析，逃离该 origin 的请求会被拒绝；中转提供的 Cookie、Authorization、Origin 与浏览器元数据不会转发。小型 HTTP 响应继续使用原有单帧形状，大型响应则使用有序的 start/chunk/end 序列，把 512 KiB 二进制切片分别编码到各帧，并对完整响应设置 128 MiB 上限。设备隧道和面向浏览器的中转均协商标准 WebSocket 压缩，因此大型 JSON 历史不会按解压后大小占用公网链路。中转同时接受两种响应形状，使服务端升级继续兼容已安装客户端；但要返回超过旧版限制的历史，客户端必须支持分片。关闭偏好、撤销设备、重启本地后端或退出应用都会关闭隧道及其本地 WebSocket，并等待清理完成。

**独立中转 authority 提供中央 Web 壳并保留 API 路径。** 经过认证的官网用户选择自己名下的在线设备后，服务会把一分钟有效的单次票据兑换成 HttpOnly 中转 session。官网一次性导出版本匹配的 Harness 壳、启动图、插件包、样式与字体，再从中转 authority 直接提供这些可缓存文件，因此加载或刷新这些资源不会消耗设备上行或隧道带宽。壳中的精确标记会为 unary 与 respond 操作选择一条复用的浏览器到官网 `/api/rpc` WebSocket；官网校验每项操作并把它转换为现有设备 `http_request` 帧，mux 与 host 事件下行仍使用独立 WebSocket。响应 start/chunk/end 帧会直接流过官网，不在服务端完整重组；分帧方式与不回退规则由[远程 WebSocket RPC 载体决策](../architecture/2026-08-16-remote-websocket-rpc-carrier.zh.md)持有。不超过 640px 时，该壳会从布局中移除已收起的侧栏轨道，只保留浮动入口，压缩会话 chrome，并让 composer 贴合动态视口与底部安全区。中转在转发前校验 Host、浏览器 Origin、账号设备所有权、session 过期时间、撤销状态与在线隧道。

**远程配置采用只读投影。** 会话和 Agent 仍然可用，因为它们正是远程控制的目的，其中包括本地 Harness 会话本来就有的命令与 workspace 能力。中央 Web 壳还需要 `settings.describe` 和 `credentials.describe`，才能在模型、通用设置、插件与 Agent 预设界面中正常显示内容而不产生传输错误。因此桌面端允许这两项已经脱敏的读取，但会在返回前改写其能力：设置不可写且不能打开宿主文档，每条凭据引用也不可写且永远不携带凭据值。设置与凭据写入、原生目录选择、路径打开、Agent preset 管理和草稿模型发现仍会在抵达回环服务器前被拒绝。隧道会先规范化 HTTP 方法大小写与百分号编码的 RPC 名称再执行拒绝，因此替代拼写无法绕过限制。

## Verification

桌面测试固定可跳过的启动账号引导、持久偏好校验、同源浏览器授权、Bearer 认证隧道启动、仅 API 的固定回环转发、非 API 拒绝、敏感 header 移除、只读配置投影、畸形投影拒绝、规范化后的特权方法拒绝、写操作继续被封锁，以及对超过旧阈值的多帧响应进行字节级精确重组。组装后的 Web 浏览器车道会在 390 × 844 下运行一轮，并拒绝对话被挤压、composer 溢出或工具栏溢出。桌面 TypeScript 构建覆盖 Electron 菜单与生命周期集成。独立官网的 MySQL 集成测试覆盖注册、session Cookie、浏览器批准、设备 token 单次领取、经过认证的设备连接、在线设备列表、连接票据兑换、中转 session 建立、无需隧道帧的中央壳交付和中转 API 承载。聚焦的 Go 测试覆盖浏览器 RPC 分帧、校验、取消、响应流传、有序隧道分片与非法顺序；Go 竞态检测、更广的 Go 测试、`go vet` 与 Vue 生产构建分别覆盖其产物。

## Alternatives considered

**把每台桌面的本地监听器直接暴露到公网。** 这种方式因 NAT 与防火墙配置违背零配置而被否决；公共入站监听会扩大攻击与支持负担，并把证书责任转移到每个用户设备。

**在 Electron 内收集官网用户名与密码。** 这种方式会使桌面端变成密码处理客户端，还要复制注册、session 与多因素认证流程。系统浏览器批准把账号认证留在官网 origin，只向桌面端提供可撤销设备凭据。

**把账号授权设为本地使用的强制条件。** 这种方式被否决，因为用户必须能够跳过引导并继续在本机使用 Harness。只有远程控制边界强制要求账号授权，因为未归属账号的设备不能安全进入账号隔离的中转系统。

**允许中转指定任意目标 URL。** 这种方式会使遭入侵或发生混淆的中转把每台桌面变成内网代理。唯一允许的 origin 是本地就绪 URL，远程路径不能替换其 scheme 或 authority。

**在官网 authority 的子路径下提供每台设备。** 既有客户端从 origin 根路径解析静态资源、API 与 WebSocket。独立中转 authority 会保留这些路径，并把官网 session Cookie 与设备流量隔离。中央壳是版本匹配的上游构建导出物，而不是需要长期维护的下游 Web 客户端 fork。

**把官网源码加入本 monorepo。** 用户要求官网成为可独立部署的同级项目，而且公网服务数据库与运营不共享桌面发布生命周期。本仓库只保留安全合并未来上游变更所需的桌面协议、安全决策与测试。

## Consequences

一个账号可以拥有多台 macOS、Windows 与 Linux 桌面，查看在线状态，并从手机浏览器连接，而无需修改家庭网络。未绑定账号的安装实例会在启动时展示这项能力，但跳过引导后仍可在本机使用。授权前远程控制不可用，授权后仍默认关闭；桌面端永远不会收到账号密码，撤销设备会同时失去新连接准入与当前在线隧道。

该服务承担了面向公网的账号安全与可用性责任：HTTPS/WSS 终止、数据库备份、边缘限速、监控、滥用响应、容量与 API 中转带宽都是运营要求。每个桌面版本必须随官网发布兼容的中央 Web 壳导出；不可变资源缓存会让普通页面加载成本很低，但壳与设备协议版本不匹配不受支持。请求体仍会在固定上限内驻留内存，因为已安装桌面隧道接收一项完整请求；WebSocket 响应分片则直接通过官网，只在发起请求的浏览器中重组。一台服务实例拥有内存中的在线设备注册表，因此横向扩容需要连接亲和或共享隧道路由层。远程 session 与 Agent 访问等同于操作该电脑上的 Harness；只读配置投影与原生操作限制不会把 Agent 的命令执行变成只读。
