# Agent Note: 移动端设置使用完整宽度

Status: implemented

[English](2026-08-16-full-width-mobile-settings.md) | 中文

## 问题

设置弹窗在所有视口宽度下都使用同一个固定双栏布局。188 像素宽的导航栏与内容内边距占去了手机视口的大部分空间，使当前分区窄到中文标签和说明每行只能显示一个字。通过官网进入远程电脑后，手机上的设置因此基本无法使用。

## 决策

在不超过 640 像素宽的视口中，共享设置外壳切换为三行网格。标题和弹窗操作位于第一行，分区列表在第二行成为可横向滚动的导航栏，当前分区在第三行取得弹窗完整宽度并独立滚动。语义化导航与分区 DOM 顺序保持不变，更宽的视口仍使用既有的固定侧栏布局。

无密钥组装 Web 测试会打开真实设置弹窗，把 Chromium 调整为 390 × 844 像素，并断言导航和内容都与弹窗等宽、内容位于导航下方、文档没有横向溢出、分区切换继续有效且关闭操作仍然可用。

## 曾考虑的替代方案

**缩窄桌面侧栏。** 不予采用，因为再窄的固定栏仍会在小屏幕上与设置行和触控目标争抢空间，并会在本地化标签更长时重新出现同类缺陷。

**把导航隐藏到另一个菜单中。** 不予采用，因为四个设置分区可以放进横向导航栏，而新增菜单会引入额外状态并降低分区的可发现性。

## 后果

手机用户可以按正常行宽阅读和操作设置，页面不会产生横向溢出。标签放不下时分区导航可能需要横向滚动，紧凑标题行与导航栏也会比单个桌面标题栏占用更多纵向空间；作为交换，当前分区始终保留完整可用宽度。断点归共享设置外壳所有，因此本机、局域网和官网中转的 Web 客户端都会获得相同行为。
