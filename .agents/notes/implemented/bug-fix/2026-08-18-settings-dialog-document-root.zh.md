# Agent Note: 挂载到文档根节点的设置对话框

Status: implemented

[English](2026-08-18-settings-dialog-document-root.md) | 中文

## 问题

设置对话框原本渲染在响应式侧边栏子树内。在窄视口打开对话框会触发壳层折叠侧边栏，从而裁剪或卸载对话框，并可能让会话界面覆盖它的控件。当祖先节点控制对话框的生命周期和堆叠上下文时，全视口 CSS 无法保证交互持续可用。

## 决策

`SettingsPanel` 通过 React portal 渲染到 `document.body`。所有权、活动条目回退、焦点放置、Escape 处理、遮罩关闭和插槽渲染仍由设置插件负责；只有 DOM 挂载点离开侧边栏子树。因此覆盖层能在响应式侧边栏折叠后继续存在，并在桌面尺寸和移动尺寸窗口中参与文档级堆叠顺序。

## 测试

设置根节点单元测试验证通过 portal 进行的对话框交互。移动设置浏览器场景会在窄视口中打开真实壳层，并在响应式侧边栏折叠后修改设置，由此证明覆盖层持续可见且能接收指针输入。

## 曾考虑的替代方案

**把对话框留在侧边栏内并提高 z-index。** 否决：z-index 无法逃离裁剪，也无法在响应式所有者卸载子树后保留子节点。

**打开设置时保持侧边栏展开。** 否决：这会让插件自有的对话框耦合到壳层导航状态，并为模态框后方不可见的内容占用紧张的移动端宽度。

## 后果

对话框现在把 `react-dom` 作为显式包依赖，并在渲染时需要浏览器 document。它的生命周期仍跟随 `SettingsRoot`，因此关闭设置或卸载插件都会正常移除 portal。覆盖层样式必须针对文档级堆叠而非侧边栏局部堆叠进行评估，同时窄桌面窗口会保留与较大窗口相同的控件和零配置行为。
