# Agent Note: DeepSeek 账户余额标识

Status: implemented

[English](2026-08-18-deepseek-account-balance-indicator.md) | 中文

## Problem

用户可以配置并消耗 DeepSeek 官方 API Key，却无法在模型提供方账户仍有多少可用资金耗尽前看到余额。只有模型请求失败后才发现余额耗尽会打断当前工作；如果让浏览器直接查询提供方，又会把 Bearer 凭据暴露给桌面 renderer 和公网远程 Web 壳。

## Decision

LLM 适配器边界持有可选的账户余额读取能力。`LlmAdapter.accountBalance()` 默认以 `BALANCE_UNSUPPORTED` 拒绝；`LlmRuntime.accountBalance()` 选择已注册提供方，校验返回的可用状态和币种唯一的十进制余额行，并脱离源对象返回结果。金额字段从提供方响应到 RPC 再到界面始终保留为十进制字符串，避免浮点舍入。

DeepSeek 直连适配器解析与模型调用相同的单次操作 `baseURL` 和凭据，再发送带应用归属信息与 Bearer 鉴权的 `GET /user/balance`。它在返回总额、赠送额与充值额之前校验 JSON 形状。提供方 HTTP、传输、取消、凭据和畸形响应失败继续使用带类型的 `LlmError`，且绝不包含密钥。

Host 通过只读 `llm.balance` RPC 暴露结果。请求只携带已注册路由名，响应只携带可用状态与余额行。桌面隧道允许把该方法转发给经过认证的远程浏览器，因为载荷不含端点、配置值或凭据。共用 Models 客户端插件会向设置页脚 slot 提供一个控件，因此桌面端和远程 Web 使用同一组件，并把它放在「设置」触发器之后、仅桌面显示的版本／更新控件之前。它会在启动时加载，在 DeepSeek 设置或凭据失效通知及连接重置后刷新，并支持点击手动刷新。折叠后的侧栏图标区不会显示该控件。

## Verification

核心测试覆盖不支持该能力的适配器、脱离源对象的结果、十进制精度保留与非法元数据。DeepSeek 适配器测试覆盖精确端点、Bearer 与应用归属标头、响应映射和畸形余额行。API 载体测试覆盖请求与响应 schema、分发、错误映射和远程转发分类。客户端测试覆盖人民币显示、明细文案、不可用状态、手动刷新、slot 注册、dispose 与 HMR 重新注册。GUI 与 Web 回归套件覆盖组装后的桌面和远程布局。

## Alternatives considered

**让浏览器直接查询 DeepSeek。** 这种方式会要求 renderer 持有原始 API Key，远程浏览器还会让凭据经过公网中转，因此被否决。Host 已经拥有凭据解析与提供方传输责任。

**把提供方余额存进官网账户数据库。** 余额属于已配置的 DeepSeek 凭据，不属于官网用户账户。镜像到官网会要求收集提供方密钥，或建立一套会产生陈旧财务数据的同步系统，因此被否决。

**把金额转换为 JavaScript 数值再格式化。** 二进制浮点无法精确保留每个十进制金额。货币符号只属于展示层，协议保留提供方原始字符串。

**强制每个适配器支持余额。** 许多提供方没有等价接口，或通过云环境账单结算。可选能力既保持这些适配器有效，也让消费方得到一个稳定的不支持结果。

## Consequences

用户可以在桌面端与远程 Web 工作前和工作期间看到当前配置的 DeepSeek 官方账户总额，并且无需打开提供方设置即可查看充值与赠送构成。密钥缺失、自定义端点不支持、网络失败或提供方拒绝时，界面显示不可用标识，不会阻断对话使用。

每次可见应用启动时，Models 客户端插件会额外执行一次提供方请求；相关配置变化或手动点击会再次请求。显示值是一个时间点的读取结果，不是逐 token 账本，因此两次刷新之间可能陈旧。自定义 DeepSeek 兼容端点只有实现 `/user/balance` 才能产生余额，否则模型调用仍可工作，而标识保持不可用。
