# Agent Note: 桌面发行入口

Status: implemented

[English](2026-09-08-desktop-distribution-entrypoints.md) | 中文

## 问题

分支仓库分发 macOS、Windows 和 Linux 安装器，提供认证局域网访问、设备中继与官网更新。独立 Electron 发行版把离线种子安装到专用配置中，并通过分帧管道传递请求。混用两者的入口或资源布局会启动缺少所需运行环境的桌面壳，或删除受支持的桌面能力。

## 决策

分支打包器把 `lib/web-main.js` 暂存为应用清单入口。它保留[桌面启动器决策](2026-08-15-electron-desktop-launcher.zh.md)说明的受管 Web 配置与原生安装器矩阵。独立打包器使用 `lib/main.js`、内置 Node.js 和 pnpm、离线种子、预加载脚本及[事务安装](2026-08-25-electron-desktop-packaging-and-updates.zh.md)。两种发行版都针对相同工作区版本构建，并接收共享 Web 与 Harness 改动。

入口由打包器选择，而不根据运行时资源是否存在进行后备选择。两种发行版明确保留各自的更新来源、配置所有权与传输权限。[官网更新决策](2026-08-16-portal-hosted-desktop-update-channel.zh.md)继续约束分支安装器。

## 考虑过的替代方案

**用独立打包器替换分支发行版。** 其目标集合与协议不提供分支的 Linux 安装器或认证局域网与中继流程。替换发布路径会删除受支持的产品行为。

**丢弃独立桌面实现。** 这会遗漏上游的独立运行环境、插件管理与事务种子安装。保留匹配的入口和打包命令，可以保留这些能力而不改变已安装分支客户端的状态所有权。

## 后果

维护者需要验证两条桌面打包路径，且不得混用其运行环境资源。构建生成两个入口与独立预加载脚本；分支暂存流程在打包前选择入口。桌面进程、打包目标、种子、更新和暂存测试覆盖各自所有者，共享连接与浏览器测试覆盖合并后的 Web 应用。原生发布执行器继续负责各平台的安装器验证。
