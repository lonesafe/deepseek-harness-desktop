# Agent Note: 只读 Workspace 文件管理器与预览

Status: implemented

[English](2026-08-16-workspace-file-manager-preview.md) | 中文

## Problem

一个对话已经标识其 Agent 工作所在的 Workspace，但对话界面无法查看该 Workspace。即使用户只想阅读 README、检查源码或查看图片，也必须离开 Harness，再用操作系统文件管理器查找目录。通过官网远程使用时，这种割裂更加明显，因为手机无法直接浏览远端电脑的文件系统。

该功能不能把浏览器变成任意文件系统读取器。它需要明确的 Workspace 所有权边界、有界载荷、经符号链接后仍成立的路径包含规则，以及能与对话输入框共存的移动端布局。

## Decision

**对话为其已注册 Workspace 持有独立文件视图。** Workspace UI 插件在 `conversation.view` 中注册 `workspace-files`。它从既有客户端投影取得当前 Session 所属 Workspace，逐层浏览目录，并提供面包屑、刷新和明确的隐藏文件开关。未纳入任何已注册 Workspace 的 Session 会显示说明性空状态，不弹出路径选择器，也不根据 cwd 推断目录。

**Host 只公开有界只读投影。** `workspace.listFiles` 与 `workspace.readFile` 先通过持久注册表解析请求中的 `WorkspaceId`，再只接受可移植的相对路径。绝对路径、反斜杠、NUL、空组件、点组件与父级组件都会被拒绝。Host 会解析规范 Workspace 根目录及每个请求目标；符号链接只有在其真实目标仍位于该根目录内时才可使用。成功响应只包含相对路径与元数据，不包含 Workspace 的绝对根路径。

单次列表最多返回 1,000 个直接子项。单次预览最多返回 8 MiB 内容。UTF-8 Markdown 与常见文本／源码／配置格式以文本传输；受支持的位图、PDF 与二进制下载以 Base64 传输。更大的文件只返回元数据和 `too-large`，不返回内容。目录与读取故障使用稳定的 `workspace-file-*` 业务错误，调用方取消信号通过既有 RPC 信号抵达文件系统工作。

**预览只负责显示，并保持在模型请求之外。** Markdown 使用共享 `MarkdownText` 渲染器，文本使用不可编辑的预格式化视图，图片放在自适应展示区，PDF 使用浏览器内嵌查看器。有界内容可以通过客户端生成的 data URL 下载，但 API 不定义创建、上传、写入、重命名、移动或删除方法。选择或预览文件绝不会把内容附加给 Agent。

**移动端导航每次只显示一个面板。** 桌面宽度下，目录和预览并排显示。宽度不超过 640px 时，打开文件会以全宽预览替换列表，并显示明确的返回操作。两个面板都会为动态输入框高度与底部安全区预留空间。远程使用时，官网继续提供同一份已编译 Web 壳，只有这些 API 调用经过既有设备中转。

## Verification

Host 单元测试覆盖正常列表、Markdown／文本／图片／PDF／二进制分类、隐藏项元数据、1,000 项与 8 MiB 上限、畸形相对路径、缺失目标、把目录当文件的拒绝、仍位于根内的符号链接，以及逃出根目录的符号链接。API 组合测试通过真实 Workspace 注册表调用两个方法，并验证类型化错误。客户端测试覆盖文件视图注册生命周期、导航、隐藏项、Markdown 预览、下载、取消、错误和无 Workspace 状态。

组装后的 Web 浏览器测试会创建真实的已注册 Workspace 与 Session，通过生产客户端图访问新 RPC，预览 Markdown 与图片，进入嵌套目录，并在 390 × 844 下重复交互。它会拒绝横向溢出、被挤窄的预览或与对话输入框相撞的视图。完整 Client／Host 构建及既有 GUI 与 Web 测试继续作为发布门禁。

## Alternatives considered

**复用操作系统文件管理器。** 这种方式无法服务远程手机，不能把浏览上下文保留在对话中，而且会暴露超出有界只读投影所需的桌面状态，因此被否决。

**把 Workspace 绝对路径发给浏览器，并公开通用读取端点。** 远程客户端不需要 Host 路径；通用路径端点也会让穿越、符号链接与权限混淆更难约束，因此被否决。注册表 identity 就是权限来源，相对路径只能选择该权限之下的后代。

**从每台桌面中转完整 Web 页面。** 官网已经提供带版本的中央 Web 壳，因此这种方式被否决。只中转 API 数据可以继续缓存静态资源，也不会把设备与服务器带宽花在展示资源上。

**在首个版本中加入文件编辑。** 写操作还需要冲突处理、编码规则、备份与恢复行为、权限交互，以及更强的远程授权政策，因此被否决。只读浏览已经能满足检查需求，同时不会悄然扩大修改边界。

## Consequences

用户可以不离开对话就查看当前项目文件，也可以通过官网连接的手机完成同样操作。该功能继续保持零配置，因为它直接使用已经与 Session 关联的 Workspace，不要求额外服务器、挂载或目录选择。

该视图刻意不是完整 IDE 或文件管理器。它没有编辑器、上传、文件系统修改、搜索、压缩包浏览、语法高亮或媒体流式传输。大目录与大文件只报告上限，不分页或流式返回；PDF 能否内嵌显示因浏览器而异。远程预览时，文件内容会经过 API 中转，因此账号与设备信任边界会向远程浏览器授予与本地相同的、对已注册 Workspace 文件的有界读取权限；用户只应为可信账号和设备开启远程控制。
