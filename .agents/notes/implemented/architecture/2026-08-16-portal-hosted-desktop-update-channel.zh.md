# Agent Note: 官网托管的桌面更新通道

Status: implemented

[English](2026-08-16-portal-hosted-desktop-update-channel.md) | 中文

## 问题

桌面用户需要在不持续关注仓库 Release 的情况下发现并安装当前 macOS、Windows 和 Linux 软件包。让所有已安装客户端直接依赖 GitHub，会使可用性受第三方 Release API 影响，把仓库特定的资产命名暴露给应用，并使产品官网无法成为权威下载入口。同时，沙箱化 Web renderer 不能只为显示更新入口就获得文件系统或进程权限。

## 决策

独立部署的官网拥有版本元数据和软件包存储。MySQL 版本记录保存版本号、标题、说明和发布时间；每项不可变资产记录平台、架构、包类型、文件名、字节数和 SHA-256。公开接口列出下载项，并依据当前版本与目标选择首选软件包；软件包字节由官网 origin 提供并支持 Range。Bearer 保护的 multipart 上传接口在服务端计算大小与 SHA-256，并原子替换同一版本、平台、架构和类型的资产。官网页面按平台和架构展示这些相同的官网下载 URL。

GitHub 仍是公开源码和构建 Release 记录，但不是已安装客户端的更新 origin。普通 GitHub Release 完成后，发布资产会先从 GitHub 下载，再上传到官网版本中心。因此官网成为下载页和桌面客户端共同使用的来源，任何更新响应都不能把客户端重定向到 GitHub。

Electron 只在加载自己的精确随机回环应用 URL 时，附加非敏感的当前版本、平台、架构和已验证官网 origin 查询信息。普通局域网页和远程页不会收到这些信息，也不会执行更新轮询。设置壳验证全部四项值，在页面启动后立即检查官网，之后每 600,000 毫秒执行一次不重叠检查。发现较新的兼容资产时，左下角「设置」触发器右侧出现紧凑更新标识；官网暂时不可用不会打断用户工作或移除本机功能。

更新标识只指向精确内部动作 `dsh-update://download`。桌面导航守卫消费该动作，不把软件包 URL 交给 renderer 或操作系统。Electron 主进程会独立再次查询配置的官网，要求选中的软件包 URL 仍属于该 origin 的 `/downloads/` 路径，在传输前询问用户，把内容写入唯一临时文件，并在原子复制到「下载」目录前验证精确长度与 SHA-256。失败、取消、长度不足、超限或摘要不匹配的传输不会留下已发布安装包，也绝不会打开。通过验证的 DMG、NSIS 可执行文件、ZIP、DEB 或已添加执行权限的 AppImage 才交给操作系统；原生应用菜单也提供同一个显式检查入口。

## 验证

桌面单元测试固定回环元数据注入、仅官网版本选择、GitHub 软件包 URL 拒绝、字节精确流传输、SHA-256 拒绝、临时文件清理和无冲突发布。浏览器测试固定完整标记校验、启动时立即发现、精确十分钟间隔、普通浏览器不启用、同源下载校验以及「设置」旁更新标识。官网测试固定语义化预发布版本排序和平台／包类型校验；MySQL 集成与生产冒烟覆盖上传、列表、首选选择、支持 Range 的下载、随机回环 origin 的 CORS 发现和摘要一致。桌面打包与本机已安装应用运行覆盖主进程动作、进度显示和系统交接。

## 考虑过的替代方案

**让每个客户端直接使用 GitHub Releases。** 这会把已安装应用绑定到 GitHub API 可用性和限流，并违背官网作为产品下载入口的定位。发布流水线可以始于 GitHub，但分发仍由官网拥有。

**给 renderer 提供 preload 文件下载 API。** 应用有意不设置 preload bridge。精确内部导航动作可以保留 renderer 沙箱，同时由主进程在触碰磁盘前重新校验全部不可信版本元数据。

**发现版本后立即自动下载。** 后台传输会在没有用户意图时消耗带宽并创建文件。版本发现自动执行，但传输和安装仍是用户的明确操作。

**有 TLS 就不再校验软件包摘要。** TLS 保护到官网的传输，却不能发现截断文件或元数据与存储不一致。精确字节数加 SHA-256 会在执行前把下载字节绑定到版本记录。

## 后果

用户会在现有左下角导航中看到不打扰操作的更新标识，并在所有平台上从同一官网取得软件包。检查在启动时和每十分钟执行，不会阻塞会话；官网暂时故障也不会停用桌面运行时。软件包会在系统交接前验证完整性，而沙箱化 renderer 永远不会获得本地文件系统权限。

官网现在承担持久二进制存储、上传凭据、数据库迁移、备份、容量和下载带宽责任。在所有预期 GitHub 资产复制到官网并验证记录摘要之前，一次 Release 尚未完成分发。客户端有意不静默安装或重启：未签名 macOS 构建仍可能需要 README 中的一次性 Gatekeeper 批准，操作系统软件包行为也始终对用户可见。
